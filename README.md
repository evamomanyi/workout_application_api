# Workout Application Backend

A RESTful Flask backend for a workout-tracking application. The API allows personal trainers to create, view, and delete workouts and exercises, and to attach reusable exercises to workouts with sets, reps, and/or duration data.

This project implements the requirements of the **Summative Lab: Flask SQLAlchemy Workout Application Backend**, including SQLAlchemy models, relationships, database constraints, model validations, Marshmallow serialization/deserialization and schema validation, migrations, seed data, REST endpoints, and automated tests.

## Features

- Flask REST API
- SQLite database
- SQLAlchemy ORM
- Flask-Migrate database migrations
- Marshmallow serialization and deserialization
- Three relational models:
  - `Exercise`
  - `Workout`
  - `WorkoutExercise`
- One-to-many and many-to-many-through relationships
- Database/table constraints
- Model-level validation
- Schema-level validation
- Re-runnable seed script
- Cascading deletion of join-table records
- JSON API responses
- Pytest test suite

## API Endpoints

### Workouts

| Method | Endpoint | Description |
|---|---|---|
| GET | `/workouts` | List all workouts |
| GET | `/workouts/<id>` | Show one workout and its associated exercises |
| POST | `/workouts` | Create a workout |
| DELETE | `/workouts/<id>` | Delete a workout |

### Exercises

| Method | Endpoint | Description |
|---|---|---|
| GET | `/exercises` | List all exercises |
| GET | `/exercises/<id>` | Show one exercise and its associated workouts |
| POST | `/exercises` | Create an exercise |
| DELETE | `/exercises/<id>` | Delete an exercise |

### Workout Exercises

| Method | Endpoint | Description |
|---|---|---|
| POST | `/workouts/<workout_id>/exercises/<exercise_id>/workout_exercises` | Attach an exercise to a workout with reps, sets and/or duration |

## Example Requests

### Create an exercise

```bash
curl -X POST http://127.0.0.1:5555/exercises \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Lunges",
    "category": "Strength",
    "equipment_needed": false
  }'
```

### Create a workout

```bash
curl -X POST http://127.0.0.1:5555/workouts \
  -H "Content-Type: application/json" \
  -d '{
    "date": "2026-08-30",
    "duration_minutes": 45,
    "notes": "Full body session"
  }'
```

### Attach an exercise to a workout

```bash
curl -X POST \
  http://127.0.0.1:5555/workouts/1/exercises/1/workout_exercises \
  -H "Content-Type: application/json" \
  -d '{
    "reps": 12,
    "sets": 3
  }'
```

For a time-based exercise:

```bash
curl -X POST \
  http://127.0.0.1:5555/workouts/2/exercises/3/workout_exercises \
  -H "Content-Type: application/json" \
  -d '{
    "duration_seconds": 1200
  }'
```

## Data Model

### Exercise

Fields:

- `id` — integer primary key
- `name` — unique, required string
- `category` — required string
- `equipment_needed` — required boolean

### Workout

Fields:

- `id` — integer primary key
- `date` — required date
- `duration_minutes` — required non-negative integer
- `notes` — optional text

### WorkoutExercise

Fields:

- `id` — integer primary key
- `workout_id` — foreign key to `Workout`
- `exercise_id` — foreign key to `Exercise`
- `reps` — optional positive integer
- `sets` — optional positive integer
- `duration_seconds` — optional positive integer

## Relationships

The application implements the relationships required by the lab:

```text
Workout
  └── has many WorkoutExercises
          └── belongs to Workout
          └── belongs to Exercise

Exercise
  └── has many WorkoutExercises

Workout
  └── has many Exercises through WorkoutExercises

Exercise
  └── has many Workouts through WorkoutExercises
```

The join table uses a unique `(workout_id, exercise_id)` constraint so the same exercise cannot accidentally be attached to the same workout twice.

## Validation Strategy

The project deliberately implements more than the minimum validation required by the rubric.

### Table/database constraints

Examples include:

- Exercise names are unique and cannot be null.
- Workout duration cannot be negative.
- Reps, sets, and duration seconds cannot be zero/negative when supplied.
- A workout/exercise pair must be unique.
- Foreign keys cannot be null.

### Model validations

SQLAlchemy `@validates` methods enforce rules such as:

- Exercise name cannot be blank.
- Exercise category cannot be blank.
- Exercise name/category lengths are limited.
- Workout duration must be an integer and cannot be negative.
- Reps, sets, and duration seconds must be positive integers when supplied.

### Schema validations

Marshmallow validates incoming API data before it reaches the database:

- Exercise name length.
- Exercise category length.
- Workout duration must be `>= 0`.
- Reps, sets and duration must be `>= 1`.
- At least one training measurement must be supplied when attaching an exercise.
- If reps are supplied, sets must also be supplied.

This layered approach helps prevent invalid data at the API, application, and database levels.

## Troubleshooting

### `ModuleNotFoundError`

Make sure you are running commands from the project root:

```bash
pwd
ls
```

You should see `app.py`, `models.py`, `routes.py`, `schemas.py`, and `seed.py`.

Also make sure the Pipenv environment is active:

```bash
pipenv shell
```

### `flask: command not found`

Run Flask through Pipenv:

```bash
pipenv run flask --app app run --port 5555
```

### Wrong Python version in Pipenv

Check:

```bash
pipenv --py
python --version
```

If Pipenv created an environment with the wrong interpreter, remove and recreate it:

```bash
pipenv --rm
pipenv install
```

If Python 3.8.13 is specifically required by your course environment, ensure that Python 3.8.13 is installed and tell Pipenv to use it:

```bash
pipenv --python 3.8.13
pipenv install
```

### Migration errors

If this is a fresh local project and you are still developing, you can remove the local database and migration directory and recreate them. Do this only if you do not need to preserve existing data.

```bash
rm -rf migrations
rm -f app.db
flask db init
flask db migrate -m "Initial database"
flask db upgrade
python seed.py
```
